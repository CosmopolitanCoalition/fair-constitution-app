## Confirmed bottleneck and bounded recommendation

The contested advisory key is **AuditService::APPEND_LOCK_KEY = 0x4155444954** (PostgreSQL classid 65, objid 1430538580), not the monetary-ledger key. Twelve one-second-spaced snapshots at 13:20:13–13:20:24 each showed **70–72 waiters** on it. An earlier snapshot had 72/73 repair workers waiting. Lock holders were executing audit inserts, public-record inserts, vote_casts inserts, vote/tally reads and a law-version insert. These samples establish that the lock is held through unrelated domain work; they are not a measured time-share breakdown or lock-hold duration.

Code explains the coupling:

- SimRepairService::action wraps one domain action, its receipt and final audit in an outer transaction.
- SimWorkerJob's repair path deliberately avoids the older outer volatile audit buffer, preserving repair atomicity.
- SimChairService opens a real chair vote, casts every seated member's public ballot and closes/adopts it in that transaction.
- The first synchronous AuditService::append acquires a transaction-scoped global lock. It remains held through subsequent ballots, public records, adoption, receipt writes and COMMIT. Governance/civic actions similarly retain it through their work and postcondition reads.
- Latest flushed repair.chair timers: 2,255 calls, 7,588,902,668 total microseconds, about **3.365 seconds per call including waiting**. Timers flush every 25 items; this partial flushed sample is not aligned with the direct-count window. Do not divide its totals by 1,588 or sum nested timers. Current audit.lock_wait instrumentation is not active for these repair actions.

**Recommended next bounded performance change:** shorten the globally serialized audit section while preserving the atomic action/receipt/audit transaction. Assess an action-local collector that performs local domain work under existing local row locks, prepares ordered audit rows, then acquires the global chain lock near transaction end to append and bind public-record audit references before the same durable commit. Keep individual event visibility wherever training/completion readers require it. Do not simply restore a volatile after-commit worker buffer, remove locks, weaken durability or aggregate away required evidence. Existing commitBatchRows explicitly warns it does not backfill public-record sequences, so it cannot be blindly reused here.

If implemented, add bounded repair audit wait / flush / owned-commit timers and exercise two concurrent repairs, failure before and after audit flush, public-record audit_seq references, receipt redelivery, savepoint rollback/buffer cleanup, and training event lookups. A failure must leave neither orphan records nor a success receipt. Start with the dominant chair path if that provides a narrower proof. Maintain the already authorized election-recovery work; this is a completed performance finding for integration/prioritization, not permission for a competing cross-task exchange.
