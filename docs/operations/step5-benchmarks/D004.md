## One bounded next recommendation

**Give each Phase 7 governor nomination one caller-owned transaction, leaving consent as its existing separate operation.** Investigate/implement this only in the Step 5 nomination path if the local fixtures confirm the mechanism and preserve behavior.

Evidence: `GovernanceStage::seatDepartmentGovernors` calls `BoardGovernorService::nominate` directly; `SimWorkerJob::execute` and the stage do not own a database transaction. `nominate`/`openNomination`/`context` perform multiple row-locking reads and appointment, seat, public-record, vote/tally and status writes without a surrounding transaction. `PublicRecordService::publish` separately owns a transaction when necessary. The later `castManyYes` already owns its consent/seating transaction. Consequently the nomination path commits individual statements and releases its row locks between them. This source-level finding, the 228 ms nomination cost per completed scope and observed WAL waits justify testing consolidation; they do not establish an exact live commit count or guaranteed speedup.

Keep the transaction bounded to **one nomination**, not a whole jurisdiction or all governors. Preserve fresh principal/current institution/residency/vacancy checks, locking, nominee order, every public record, consent vote and tally, separate consent semantics, and existing retry/deferral policy. A rollback must also restore the simulation's buffered audit checkpoint; the stage catches nomination exceptions, so rolled-back acts must not later enter its successful audit batch. Keep the nomination timer outside the transaction return so its owned durable commit is measured. No durability relaxation, new index, worker increase, or Redis change is recommended.

Developer validation should establish the reduction in owned commit boundaries in a real PostgreSQL fixture, identical successful nomination/consent/term/clock outputs, atomic rollback after partial nomination writes and public-record/vote failure, correct buffered-audit truncation, existing outer-caller rollback, and concurrent nominations/principal departure without duplicate or unauthorized seating. Retain existing governor and term regressions. Do not report a production gain from fixture query counts. Return one completed, tested, pushed handoff for manual relay. Demo will capture a fresh Phase 7 baseline, use the established bounded halt/drain/refresh procedure if deployment is still justified, and compare completed windows with nominations/seatings per scope recorded alongside throughput.
