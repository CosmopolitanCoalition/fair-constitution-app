## Completed deployment repairs

**M1 is repaired.** `deploy.sh` now inspects an existing Matrix volume read-only before changing `.env` or starting services. It compares the parsed stored server name exactly. A mismatch or invalid stored configuration stops deployment and preserves the databases, volume and existing configuration. The automatic database/volume deletion branch is removed. No-volume and empty-volume first installs remain supported.

**M2 is repaired.** Public Matrix and MAS start only after configuration validation. A fresh installation stages every generated sibling file in a temporary directory; a failed generator, absent output, invalid YAML, known development credential, or mismatched secret stops before installation/service start. Staging directories are excluded by `.gitignore`, and generator output containing credential values is kept inside the private temporary stage rather than printed. A valid existing bundle is reused, including MAS encryption/signing keys. Existing rooms with an invalid bundle require configuration repair instead of silently rotating their authentication keys. Both repairs are covered by the tests above. They are completed development/internal testing scopes, not pending build items.

Staging permission check: the app container runs as UID 0 under the checked-in image/service configuration. The actual generator also succeeded with all outputs redirected into a Linux mode-0700 stage owned by UID 1000. The validator explicitly runs as UID 0 with read-only mounts, so it can inspect that private stage without broadening its file permissions. `git check-ignore` confirmed a staged secret YAML path is excluded. These checks did not change the running configuration or print generated credentials.

## Remaining confirmed build repairs

The following defects are established by current executable branches. They are additional findings except where marked as an existing issue rechecked. These scopes remain unrepaired.

| ID | Defect and exact trigger | Build outcome needed |
|---|---|---|
| M3 | **Rerunning a join package changes the node identity.** Both deployment scripts execute `federation:init --rotate` whenever `--join`/`-Join` is present, including a rerun with an existing membership and a consumed single-use join key. `rotate()` explicitly generates a new server identity, invalidating the identity already admitted by the host. In addition, [deploy.ps1](../../../deploy.ps1) unconditionally calls `key:generate --force` on every run, while the Linux non-join path preserves an existing key. This can leave the existing signing private key encrypted under the previous application key. | Preserve application/federation identity during ordinary deploy and resume. Reuse a current membership's resume path instead of consuming an adoption key again. Keep any deliberate clone re-key as a separate explicit operation. Cover Linux and Windows reruns. |
| M4 | **Linux bootstrap can register against a different Compose project from the one it deployed.** [bootstrap.sh](../../../bootstrap/bootstrap.sh) passes an explicit `--project` through to `deploy.sh`, but its post-deploy command is always `docker compose -p "$PREFIX"`. Deploy itself also preserves an existing configured project name, which can differ from the prefix. As a result `federation:init`, transport registration and directory publication target the wrong project. These failures are warnings and the bootstrap still prints completion. | Use the same resolved Compose project for deployment and all subsequent registration/readiness commands. Test an explicit custom project and an existing project whose name differs from its container prefix. |
| M5 | **The installer's join blocks initial serving on the whole foundation transfer.** `deploy.sh` runs [ClusterJoinCommand](../../../app/Console/Commands/ClusterJoinCommand.php) before frontend assets and nginx are prepared. That command calls `MirrorService::joinHost()` with its synchronous default, so a large download/drain keeps the install in the terminal and leaves the new node's progress UI unavailable. It does not use the background join path already built for the browser. | Admit and dispatch resumable sync, bring up the UI, and report truthful sync state. A simulated interruption must resume the same membership and show progress without repeating completed pages. |
| M6 | **Paginated seed finalization returns to unbounded world statements.** Both seed branches in [MirrorService](../../../app/Services/Mirror/MirrorService.php) stamp all null `jurisdictions.authoritative_server_id` values in one update, then count all remaining null rows. [FoundationServeService::totalRows](../../../app/Services/Federation/FoundationServeService.php) also computes a whole-table count on a cache miss. The keyset pages do not bound those separate statements. | Stamp authority within bounded imported pages or a resumable finalization ledger. Use bounded verification and maintained/cached progress metadata without repeated table scans. Preserve the rule that a mirror claims no local authority. |
| G1, existing issue rechecked | [SimRun::PHASE_KINDS](../../../app/Models/SimRun.php) still has no work in `verifying`; [SetupController::completeStep5](../../../app/Http/Controllers/SetupController.php) still advances without checking current run status/residue. | Existing acceptance/readiness build item remains valid. |
| G2, existing issue rechecked | [SimStartCommand::enumerateCohorts](../../../app/Console/Commands/SimStartCommand.php) still terminates its offset loop on newly inserted `$n > 0`. A fully pre-enrolled first page can stop a resume before later missing pages. | Existing stable-cursor/resume repair remains valid. |
| G3, existing issue rechecked | [SimSnapshot::computeWorld](../../../app/Services/Demo/SimSnapshot.php) still performs global counts/sums and chamber/member-existence aggregation; the command still declares a fixed 25,000-row enumeration chunk. | Existing bounded setup/progress work remains valid. New transport-finalization finding M6 should join this performance scope. |
