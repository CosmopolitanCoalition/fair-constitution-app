# Setup and simulated civic rehearsal audit

13 September 2026. Code inspection only. No database queries, test runs, simulation controls or world changes were performed for this audit. This records existing code and proposed checks, not passing results.

The operator has directed that all multi-user rehearsal use simulated participants for now. Physical-device and human-attendee rehearsal is deferred. Setup and world-generation review follows the remaining demo workflows.

## What is implemented, and what has not been established

All five civic areas have implementation code and targeted tests. That does not establish that every attendee journey works through the current browser screens. Screen consolidation, domain-rule coverage, simulation completion and complete user-journey verification are different claims.

## Reuse Step 5 and Dev tools appropriately

The simulation phases are people/cohorts, identities, elections, counting, seating, training, governance, judiciary, civic life and stipends. The ordinary judiciary stage seats a bench; it does not itself exercise a criminal-case hearing. No simulation stage supplies a full multi-client room rehearsal or an interjurisdictional consent journey.

## Test isolation and a reusable simulated rehearsal

[phpunit.xml](../../../phpunit.xml) defaults to SQLite memory, but that is not sufficient isolation for every test. [LivePgConnection](../../../tests/Concerns/LivePgConnection.php) explicitly chooses `LIVE_PG_DATABASE`, falling back to `fair_constitution`. Several classes have their own equivalent helper. Their transaction rollback does not make external queue, cache, files or service effects isolated.

| Candidate group | Inspected posture | Useful coverage |
|---|---|---|
| `StvDroopGregoryTest`, `PegQuorumTest`, `BicameralDualAgreementTest`, `PanelSizingTest`, `SetupLadderTest`, `SimScopeTest` | Pure calculations or unsaved model fixtures. No need to populate a world. | Counting, thresholds, court sizing, setup routing and aspect dependencies. |
| `ElectionNavigationTest`, `LegislatureWorkspaceTest`, `SessionArchiveTest`, `InstitutionRoomTest` | Explicit isolated SQLite fixtures. Room dependencies are replaced in the tests. | Place retention, pagination, exact records, participant identity and private-room denial. |
| `tests/js/roomParticipants.test.mjs`, `tests/js/roomPresentation.test.mjs` | Synthetic participants and controlled replies. | Batched identity resolution, stale/cross-room responses, current seating and witness placement. |
| `CaseLifecycleTest`, `ElectionStageTest`, `CountingStageTest`, `GovernanceStageGrowthTest`, `UnionDualSupermajorityTest`, `DisintermediationUnanimityTest`, `BorderAffectedAreaDenominatorTest`, `RestorationJudicialReviewTest`, `FederationRoundTripTest` | Explicit PostgreSQL connection despite the suite default; some depend on existing world rows. | Reusable sequences, but redirect all database connections to a disposable fixture database and isolate service side effects before running. Do not run these against the current world by assumption. |

Proposed rehearsal runner: create a small isolated jurisdiction tree and distinct synthetic actors; exercise actual HTTP/form boundaries with separate authenticated sessions; assert resulting records, refusals and follow-up links; use separate generated-media clients for room calls; record pass/fail/skip per scenario. Never count a skipped scenario as passed. Do not impersonate the operator or publish synthetic testimony into existing civic records. Keep fixture identities, Matrix rooms and queues separate from the current world.

This audit did not discover a checked-in full browser/transport rehearsal runner. Existing room JavaScript tests are reusable components of one. Earlier transport results remain documented in [LIVE_ROOMS.md](LIVE_ROOMS.md); they were not repeated here. Physical-device checks remain deferred under the operator's current instruction.

## Setup correctness and performance follow-up

Current pipeline ownership is clear: [GeodataRun](../../../app/Models/GeodataRun.php) plus the Python [supervisor](../../../scripts/etl/supervisor.py) run boundary/raster ingestion, parent resolution/population attribution, finalization and scan; [AutoscaleEnumeration](../../../app/Support/AutoscaleEnumeration.php) and districting workers produce maps; [ProvisionRunControl](../../../app/Services/Provision/ProvisionRunControl.php) builds a resumable institution ledger; the Step 5 services populate those institutions. [HostCapacity](../../../app/Support/HostCapacity.php) and [memory_budget.py](../../../scripts/etl/memory_budget.py) already derive worker/memory limits. Preserve this ownership and the two-direction lane rules when optimizing.

| Priority | Verified code issue | Proposed change and acceptance evidence |
|---|---|---|
| First: completion means an inspected world | `SimRun::PHASE_KINDS['verifying']` is empty. The pump can pass through it with no acceptance work, while `SimSnapshot::phaseOverview` labels it “Verifying the world.” `SetupController::completeStep5` advances the ladder without checking current run status or review residue. | Add bounded, resumable acceptance checks and an honest completion contract. Check required artifacts for selected aspects and report deferred/failed jurisdictions. Preserve a deliberate operator choice to finish with documented exclusions; do not silently claim verification. |
| First: resume must visit the remaining roster | `SimStartCommand::enumerateCohorts` loops while the inserted count `$n > 0`. On resume an already-enrolled first page inserts zero through `NOT EXISTS`, ending the loop before later missing pages. | Terminate by rows scanned, not rows newly inserted. Persist a stable cursor. Fixture: pre-enroll the first page, leave later pages absent, resume twice and prove complete enrollment without duplicates. `ProvisionRunControl::materializeLedger` already separates scanned/inserted counts and persists its cursor. |
| Next: stop progress pages from repeatedly scanning the planet | `SimSnapshot::computeWorld` performs global counts/sums and a legislature/member existence aggregate. The result is cached for only ten seconds. `stages` and `ledger` also aggregate the whole run each poll. | Maintain/checkpoint run counters and refresh expensive totals asynchronously in bounded batches. Progress views should read snapshots. Measure request latency and query work with multiple simulated pollers, not just one cached request. |
| Next: bound setup statements | `SimStartCommand` uses fixed 25,000-row chunks, offset pagination, a global eligible count and a whole-subtree temporary roster. `AutoscaleEnumeration::deriveOrderingKeysOnLedger` performs whole-ledger updates, geometry-bound calculations and ranking. These statements can remain expensive even though later work is chunked. | Replace monolithic preparation with resumable staged/keyset work and host-derived chunk sizing. Preserve deterministic ordering, seat budgets and exactness. Test halt/resume and peak resource use on small and large synthetic tree shapes. |
| Then: identify the actual slow stage before changing algorithms | Geodata and provisioning already have durable work ledgers, host-derived lanes, review gates and timing hooks. Civic simulation already records sub-stage timings through `SimTimer`. | Use existing bounded per-item timing/cost records, not full-world geometry diagnostics. Benchmark cold import versus resumption and reuse of accepted geodata/maps. Prioritize measured CPU, memory, disk, audit-chain or database contention. Do not lower constitutional requirements to make a run faster. |

After the remaining economic/civic journeys settle, validate two setup outcomes independently: a populated walkable synthetic demo, and a player-ready world with the intended founding mode, authority and consent behavior. A successful import or a “done” simulation counter is insufficient evidence for either outcome.

Read-only spot checks during the 13 September organization pass reinforce the need for those acceptance checks. `'Eua fo'ou Trading Co.` (`cf7bb400-913e-42a9-bdf4-63d64cee6eec`) displayed workers and a seated board but no recorded ownership structure or organization representative. `'Eua fo'ou Community Health Corporation` (`01a07ce0-b631-7181-af3f-b8157a7a8862`) displayed three seated governors and an unfilled chair, with a required chair election and no participant ballot control. These are two inspected examples, not an aggregate claim about the whole world. Later setup checks should verify the prerequisites of the chosen economic and institutional scenarios, including usable agents/structures and completed board composition, rather than relying on institution counts alone.
