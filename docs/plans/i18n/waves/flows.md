## The load-bearing caveat: flows.js is GENERATED

`flows.js` carries `GENERATED — do not edit` (built by `scripts/education/build_education_payload.mjs`). So it **cannot carry hand-added `$t()` keys** — the next regeneration would erase them. The extraction is therefore built around a key that is a **pure function of the English text**, so no key ever needs to live in flows.js.

## The contract — resolve the key at runtime

The catalog is the `flows` namespace (`resources/js/i18n/locales/en/flows.json`). The **key within that namespace** is `slug(text)_<first 8 hex of sha256(text)>` — a pure function of the raw string, so a consumer computes it from the string it already holds:

```js
// keep in sync with scripts/i18n/extract_flows.mjs flowsKey()
function flowsKey(raw) {                 // returns the key WITHIN the flows namespace
  const s = String(raw).replace(/\s+/g, ' ').trim();
  const slug = s.toLowerCase().replace(/[^a-z0-9]+/g, '_').replace(/^_+|_+$/g, '').slice(0, 40) || 'step';
  return `${slug}_${sha256hex(s).slice(0, 8)}`;   // browser: any small sha256 hex impl
}
// e.g. flowsKey('Accept per bylaws') === 'accept_per_bylaws_4ff14409'
```

How you turn `(namespace='flows', key)` into a `t(...)` call is lane 6's wiring choice — **no component references a namespace catalog yet** (`registry`, `c_*`, and now `flows` are all extracted-but-not-wired), so there is no house form to match against today; pick one and the other pending namespaces follow it. The keys are flat inside the namespace object (the app sets vue-i18n `flatJson: true`, so a dotted key is a literal, not a path).

Because vue-i18n falls back to `en` (and `missingWarn`/`fallbackWarn` are off), wiring this is **safe to land before translations exist**: an unresolved key renders the English source string, exactly as today.

### Recommended split of work

- **lane 15** (owns the generator): optionally have `build_education_payload.mjs` call the same `flowsKey()` and emit a parallel `keyForStep` map, so consumers need no runtime hashing. Either way the key scheme is identical.
- **lane 6** (owns the flyout markup): wrap the rendered flows strings in `t(flowsKey(...))`. The catalog already carries the English, so the visible result is unchanged until a translation is verified.
